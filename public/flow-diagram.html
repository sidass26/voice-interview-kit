Why research-first? Research is baked directly into the voice agent's system prompt at session creation. This means every research-driven question (Reddit Qs, local food, common mistakes) is available from the very first question. No mid-session injection needed.
Phase 3 — Voice Interview (5 phases)
API Create realtime session (research already baked in)
Builds system instructions from:
1. Destination-aware persona — "You're dying to visit {destination}, pump them for trip intel"
2. Intake context — what we already know (don't re-ask)
3. Itinerary context — day-by-day interview flow plan
4. Research context — ALWAYS included (per-city food, activities, Reddit Qs, unique angles)
5. Topic tracking rules — anti-repetition, mandatory topics

Session config includes input_audio_transcription: { model: "gpt-4o-mini-transcribe" }
POSTs to OpenAI Realtime Sessions API → returns ephemeral key
Status: ready → interviewing
GET /api/sessions/[id]/realtime → instruction-builder.ts
VOICE AGENT Live interview via WebRTC
Connection: Browser ↔ OpenAI Realtime API via WebRTC (SDP offer/answer)
Audio in: User's mic → WebRTC track → OpenAI
Audio out: OpenAI → WebRTC track → browser <audio> element
Data channel: JSON events for transcript + control

Transcript capture (both sides):
• response.audio_transcript.done → interviewer (bot) text
• conversation.item.input_audio_transcription.completed → interviewee (user) text

Mic mute: stream.getAudioTracks()[0].enabled = false — bot waits
interview-panel.tsx (WebRTC setup)
Interview flow (5 phases)
Phase 1: Overview 2-3 min. How the trip came about, general vibe.
Phase 2: Day-by-day Walk through each city block. Per day: highlights, food, issues.
Phase 3: Cross-cutting Best restaurant, budget breakdown, what they'd change, who it's for, tips.
Phase 4: Research rapid fire "We researched popular questions about {destination} — quick fire round!" 3-5 research-driven Qs from Reddit/web.
Phase 5: Close "One thing you'd tell someone planning this trip?" Thank and end.
🎤 Critical fix (March 2026): input_audio_transcription must be enabled in the session config. Without it, the Realtime API never generates text for user speech — the bot hears the audio but no transcription events fire. This caused transcripts to contain only bot messages, leading to hallucinated extractions.
USER Ends interview
Closes WebRTC + data channel. Stops mic stream.
Sends all transcript entries (both bot AND user) + duration via PATCH /api/sessions/[id]
Saves to transcripts.raw_entries
Status: → processing
interview-panel.tsx → PATCH /api/sessions/[id]
Phase 4 — Post-Processing Pipeline
USER Clicks "Generate Article"
Triggers POST /api/sessions/[id]/process → runs 4-step pipeline
STEP 1 Transcript cleanup
GPT-4.1 · temp 0.3
Fix speech-to-text errors, remove filler words, fix punctuation
Preserve exact details (names, prices, dishes)
Mark unclear sections with [unclear]
Saves cleaned text to transcripts.cleaned_text
transcript-cleaner.ts + prompts/transcript-cleanup.ts
STEP 2 Structured extraction (with evidence log)
GPT-4.1 · temp 0.2 · JSON mode
Two-pass approach: find interviewee quotes first, then extract from quotes only

Critical rule: Interviewer questions ≠ facts
If bot asks "Did you try the shuwa?" and user says "no" → shuwa is NOT extracted
Only the interviewee's confirmed statements become data

Evidence log (_evidenceLog): every extracted fact must cite a direct transcript quote
If no quote exists → fact is not included

Outputs: highlights, food, restaurants, budget, per-day breakdown, suggested articles
All budget fields nullable — null means "not mentioned"
extractor.ts + prompts/extraction.ts
🔍 Research leak prevention: The extraction model receives ONLY the cleaned transcript — it does NOT receive research data. Research-informed questions asked by the bot appear in the transcript, but the extraction prompt explicitly instructs: "Interviewer questions are NOT facts — only extract what the interviewee confirmed." The evidence log ensures every fact is traceable to a user quote.
STEP 3 Article generation
GPT-4.1 · temp 0.7 · 1200-2000 words markdown
First-person voice ("I" / "we"). Cross-checks against evidence log.
Sections: intro, highlights, loved, disappointments, food, logistics, budget, who it's for, tips
Skips sections with no real data — honest gaps beat fabrication
No AI-speak ("hidden gem", "feast for the senses", "nestled in")
article-generator.ts + prompts/article.ts
STEP 4 WordPress payload builder
Converts markdown → HTML, generates title, slug, excerpt, categories, tags
Stores as WordPressPayload — ready to publish but NOT sent anywhere yet
Status: → completed
payload-builder.ts
Phase 5 — Review
USER Review page — 6 tabs
Overview: session metadata, intake summary
Transcript: raw entries (timestamped, both bot + user) + cleaned text
Research: full research JSON with per-city data
Extraction: structured data + evidence log — verify every fact is sourced
Article: full markdown article (copy button)
Payload: WordPress-ready JSON (stored, not sent)
/review/[sessionId] → review-panel.tsx

🤖 Agent Coordination

Research Agent (GPT-4.1 + web search)
    │
    │  Runs BEFORE interview starts (user waits 15-30s)
    │  Output: structured research with per-city hints, Reddit Qs
    │
    │  Research MUST complete before interview can begin
    │
    └──→ Baked into Voice Agent system prompt (always available from Q1)
              │
              ▼
Voice Agent (GPT-4o Realtime, WebRTC)
    │
    │  Persona: "I'm planning my own trip to {destination}"
    │  Walks through itinerary day-by-day
    │  Uses research to ask sharper questions throughout
    │  Phase 4: Research rapid fire — Reddit Qs the user can answer
    │
    │  Transcribes BOTH bot and user speech (gpt-4o-mini-transcribe)
    │  Output: raw transcript entries (interviewer + interviewee)
    │
    ▼
Processing Agents (GPT-4.1, sequential pipeline)
    │
    ├── Transcript Cleaner: fix speech errors, keep details
    │
    ├── Extractor: ONLY extracts interviewee's confirmed statements
    │         Two-pass: find quotes first, then extract from quotes
    │         Evidence log required — no quote = no extraction
    │         DOES NOT receive research data (prevents contamination)
    │
    ├── Article Writer: first-person article from extracted data
    │         Cross-checks against evidence log
    │         Skips sections with no data
    │
    └── Payload Builder: WordPress-ready JSON (not sent yet)
